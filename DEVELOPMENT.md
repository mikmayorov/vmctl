# Разработка vmctl

Администраторская инструкция и справка по командам находятся в [README.md](README.md). Этот файл описывает устройство проекта и подготовку изменений.

## Устройство

- `vmctl` — исполняемая точка входа; `vmctl.py` — разбор команд и порядок операций.
- `vmcreate.py` — проверка запроса, XML домена, создание диска и cloud-init.
- `inventory.py` — чтение локальных ВМ через `virsh`.
- `netbox.py` — запросы к NetBox и преобразование записи ВМ в локальные параметры.
- `config.example.toml` и `examples/` — переносимые образцы без данных конкретного хоста.
- `tests/` — модульные тесты. Сторонних Python-зависимостей нет.

Каждый хост работает самостоятельно из `/opt/vmctl`. `config.toml`, `netbox.key`, `state/` и `local/` исключены из Git. В них размещают местные настройки, токен, созданные XML/данные cloud-init и рабочие запросы ВМ. Диски и установочные образы располагаются в хранилище хоста.

## Режимы и инварианты

При заданном `netbox.key` в конфигурации, файле `/opt/vmctl/netbox.key` или переменной `NETBOX_TOKEN` NetBox является источником истины для описания ВМ и требуемого состояния. `create` сначала создаёт запись со статусом `planned`, читает сохранённые поля обратно, затем определяет ВМ в libvirt и переводит запись в `staged`. Стандартные поля NetBox содержат имя, кластер, устройство, CPU, память и диск; `local_context_data.vmctl` содержит источник установки, пути, мост и каталог дисков. Кластер определяется по устройству хоста в NetBox, а не дублируется в конфигурации. Устройство выбирается по имени и, при необходимости, slug площадки и tenant; неоднозначный результат вызывает ошибку.

Каждая команда, изменяющая ВМ в управляемом режиме, сначала записывает требуемое состояние в NetBox. Неудачная запись запрещает локальное изменение. Локальная ошибка после записи оставляет запись NetBox для повторного `sync` и проверки `audit`; автоматического отката нет. Без ключа команды работают только локально, а `sync`, `audit`, `adopt` недоступны.

`adopt` проверяет, что устройство хоста уже существует и привязано к кластеру; устройство и кластер программа не создаёт. Команда предварительно читает локальные ВМ, затем создаёт только отсутствующие записи NetBox. Для импортированной ВМ источник установки обозначен как `existing`: параметры и питание можно сверять, но автоматически восстановить исчезнувшую ВМ через `sync` нельзя. Интерфейсы и IP-адреса импорт пока не создаёт.

## Проверка изменений

```bash
python3 -m unittest discover -s tests
git diff --check
./vmctl --config config.example.toml --dry-run create examples/ubuntu-iso.toml
```

Перед публикацией проверяйте выбранный коммит на испытательном хосте: запускайте тесты во временном каталоге, затем `doctor`, `audit` и `adopt --dry-run` с его местной конфигурацией. Для проверки записи NetBox и создания ВМ используйте отдельную тестовую ВМ. Запишите, какой коммит и какие сценарии реально прошли испытание.

Работайте в локальной ветке разработки. В `main` переносите только проверенные универсальные изменения без стендовых заметок и секретов. Перед отправкой выполните тесты, просмотрите `git show --stat` и состав дерева `main`; отправляйте только `main` или тег, созданный на ней. Исходники, README, образцы и тесты должны входить в публикуемый коммит.
