# vmctl

Команды для создания и управления виртуальными машинами libvirt/KVM. Каждый хост самостоятельно работает из `/opt/vmctl`. При наличии ключа NetBox описание ВМ и требуемое состояние хранятся в NetBox, а `vmctl` применяет их в libvirt.

## Использование

`vmctl -h` показывает команды по задачам со всеми аргументами; `vmctl КОМАНДА -h` и, например, `vmctl disk add -h` показывают справку и пример для конкретной операции.

### Установка

Нужны Python 3.11+, работающий libvirt/KVM, `virsh`, `qemu-img`, каталог для дисков и сетевой мост. Для создания ВМ из cloud image дополнительно нужен `xorriso`.

На хосте с правами на `/opt`, libvirt и хранилище ВМ:

```bash
git clone https://github.com/mikmayorov/vmctl.git /opt/vmctl
cd /opt/vmctl
cp config.example.toml config.toml
chmod 600 config.toml
ln -s /opt/vmctl/vmctl /usr/local/bin/vmctl
```

В `config.toml` укажите:

| Поле | Что указать |
| --- | --- |
| `host.libvirt_uri` | Адрес локального libvirt, обычно `qemu:///system`. |
| `host.domain_xml_directory` | Необязательно: каталог постоянных XML libvirt, если он отличается от `/etc/libvirt/qemu`. Нужен для ссылок `current-guest/`. |
| `storage.directory` | Существующий каталог для дисков ВМ. |
| `network.bridge` | Существующий мост на хосте. |
| `netbox.url` | Адрес вашего NetBox, если нужен учёт ВМ. |
| `netbox.device` | Точное имя устройства этого хоста в NetBox. |
| `netbox.site` | Slug площадки, если устройства с таким именем есть на разных площадках. |
| `netbox.tenant` | Slug tenant, если имя и площадка всё ещё не дают однозначный выбор. |
| `netbox.key` | API-ключ NetBox. Можно вместо него создать файл `/opt/vmctl/netbox.key` с правами `600` либо задать `NETBOX_TOKEN`. |

Для работы с NetBox заранее создайте в нём кластер и устройство хоста, затем привяжите устройство к кластеру. Сам кластер в конфигурации не указывается. Для API-пользователя создайте [права по инструкции](docs/netbox-permissions.md). Если ключ не задан ни одним из трёх способов, `vmctl` работает только локально и не ведёт учёт ВМ в NetBox; `prepare`, `sync`, `audit` и `adopt` недоступны.

Проверьте установку командой `vmctl check`. Для обновления выполните `cd /opt/vmctl && git pull --ff-only`, затем снова `vmctl check`.

### Где находятся параметры ВМ

После создания записи в NetBox исходные параметры меняют там. Файл TOML для `prepare` или `create` — первоначальный запрос: последующий `sync` читает сохранённую запись NetBox, а не этот файл. Не правьте управляемую ВМ напрямую через `virsh`, если нужное изменение поддерживает `vmctl`: это создаст расхождение. Фоновой синхронизации нет: после правки NetBox запускайте `sync` сами; `audit` только проверяет.

| Параметр | Где менять | Что делает `vmctl` |
| --- | --- | --- |
| Имя и устройство хоста | Поля ВМ в NetBox при создании | `sync` ищет ВМ по имени на устройстве этого хоста. Переименование и перенос ВМ на другой хост автоматически не выполняются. |
| UUID libvirt | Поле `Serial` ВМ в NetBox | Для новой ВМ создаётся до записи в NetBox и используется в XML; `adopt` копирует UUID существующей ВМ. `audit` проверяет совпадение. |
| Статус, vCPU, память, Description | Поля ВМ в NetBox | `sync` читает и применяет к поддерживаемой ВМ. Команды питания сначала меняют статус в NetBox. |
| Автозапуск | `Start on boot` в NetBox | Меняйте через `vmctl autostart ИМЯ` или `vmctl autostart-off ИМЯ`: команды обновляют NetBox и libvirt. `sync` не переключает автозапуск. |
| Диски | Virtual Disks ВМ в NetBox: `Size` — ёмкость в МиБ, `Description` — полный путь к диску на хосте; поле `Disk` ВМ показывает общий размер | `sync` читает путь из `Description` и обновляет постоянный XML; у работающей ВМ изменения дисков вступают в силу после выключения и запуска. Размер существующего qcow2 не меняет. |
| Подключённые ISO и другие CD-ROM носители | Virtual Disk с `Description` = полный путь и `Size` = размер в МиБ; имя и целевой привод связаны в `local_context_data.vmctl.mounted_media` | `adopt` создаёт и обновляет запись носителя. Его размер входит в суммарный `Disk` ВМ в NetBox, но не считается записываемым диском для libvirt. |
| Интерфейсы и MAC | Интерфейсы ВМ и их Primary MAC в NetBox | `sync` обновляет постоянный XML; у работающей ВМ изменения интерфейсов вступают в силу после выключения и запуска. При отсутствии primary MAC сначала создаёт его в NetBox. |
| IPv4/IPv6 | IPAM: адрес назначается интерфейсу ВМ, затем при необходимости выбирается как Primary IPv4/IPv6 у ВМ | Проверяет привязку primary IP. Сеть внутри гостевой ОС не настраивает. |
| Мост и источник установки | `local_context_data.vmctl` записи ВМ | `bridge` задаёт мост по умолчанию, `interface_bridges` — мосты отдельных интерфейсов. Путь каждого диска хранится в `Description` его Virtual Disk; старый `disk_paths_by_name` читается для совместимости. Перенос существующего диска не выполняет. |
| VNC/SPICE: тип, IP хоста, порт, пароль | `local_context_data.vmctl.display` записи ВМ | `sync` записывает их в XML libvirt; `check ИМЯ` показывает фактические значения, а `audit` скрывает пароль. |
| Подключение к NetBox, каталог хранения и мост по умолчанию | `/opt/vmctl/config.toml` конкретного хоста | Использует для связи с NetBox и первоначального запроса ВМ. Изменение файла не переписывает созданные записи. |

При `prepare` создаются первый виртуальный диск и один интерфейс, по умолчанию `inet`, с primary MAC. Дополнительные диски и интерфейсы можно добавить через команды `vmctl` или в NetBox с последующим `sync`. В NetBox меняйте нужные значения внутри `local_context_data.vmctl`, сохраняя остальные поля. Значение `display` по умолчанию:

```json
{"type": "vnc", "listen": "127.0.0.1", "port": "auto"}
```

Допустимые `type`: `vnc`, `spice`, `none`. Для VNC/SPICE `listen` — IP хоста, `port` — число от `5900` до `65535` либо `"auto"`; `password` добавляется в тот же объект. При прослушивании не на `127.0.0.1` или `::1` пароль обязателен. Пароль VNC ограничен 8 байтами. Он хранится в NetBox и в защищённом XML на хосте. Рекомендуемый вариант доступа — оставить `127.0.0.1` и использовать SSH-туннель.

В NetBox откройте запись ВМ и измените её поле **Local Context Data**: путь `vmctl.display`. Например, задайте `{"type":"vnc","listen":"192.0.2.10","port":5906,"password":"demo1234"}` внутри существующего объекта `vmctl`, сохранив остальные его поля. Затем выполните `vmctl --dry-run sync ИМЯ` и `vmctl sync ИМЯ`. У работающей ВМ новый дисплей появится после выключения и запуска. Значение `password` находится в NetBox как обычный JSON-текст и выводится командой `check ИМЯ`; право просмотра ВМ следует давать с учётом этого.

### Команды

| Команда | Действие |
| --- | --- |
| `vmctl check` | Проверить инструменты, libvirt, хранилище, мост, доступ к NetBox, версию libvirt, пулы и сети. |
| `vmctl check ИМЯ` | Показать фактическое состояние ВМ, ресурсы, диски, интерфейсы, дисплей и данные NetBox. |
| `vmctl list` | Таблица локальных ВМ: питание, CPU, RAM и диск в десятичных GB (1 GB = 10⁹ байт, округление до 0,001 GB), автозапуск, host-интерфейсы, Primary IPv4/IPv6 из NetBox, URL дисплея и UUID. При недоступности NetBox локальные данные выводятся без IP. |
| `vmctl start ИМЯ` | Запустить ВМ. |
| `vmctl shutdown ИМЯ [--force]` | Запросить штатное выключение и ждать до 60 секунд; при отсутствии ответа вернуть ошибку. `--force` выключает немедленно, как отключение питания. |
| `vmctl reboot ИМЯ` | Запросить штатную перезагрузку ВМ. |
| `vmctl autostart ИМЯ` / `vmctl autostart-off ИМЯ` | Включить / выключить запуск ВМ вместе с хостом. |
| `vmctl prepare ФАЙЛ` | Создать ВМ, диск, интерфейс и MAC только в NetBox. Затем можно назначить IP и настроить дисплей до локального создания. |
| `vmctl create ФАЙЛ` | Выполнить этапы `prepare` и первого `sync` подряд, без паузы для правок в NetBox. Без ключа создаёт только локальную ВМ. |
| `vmctl sync [ИМЯ] [--purge]` | Создать или сверить локальную ВМ по NetBox. Без имени обрабатывает все ВМ, привязанные к устройству этого хоста. Требуется ключ. |
| `vmctl disk add ИМЯ ДИСК --size-gb N` | Добавить виртуальный диск. |
| `vmctl disk remove ИМЯ ДИСК [--purge]` | Отключить дополнительный диск; `--purge` удаляет его управляемый файл. Загрузочный диск так удалить нельзя. |
| `vmctl nic add ИМЯ ИНТЕРФЕЙС [--bridge МОСТ] [--mac MAC]` | Добавить интерфейс и primary MAC. |
| `vmctl nic remove ИМЯ ИНТЕРФЕЙС` | Удалить интерфейс и MAC; IP предварительно снимите в NetBox IPAM. |
| `vmctl delete ИМЯ [--purge]` | Удалить выключенную ВМ; файлы дисков сохраняются, если не указан `--purge`. |
| `vmctl audit` | Сравнить локальные ВМ с NetBox; изменения, записанные в XML работающей ВМ до следующего запуска, показывает как `PENDING RESTART`. Требуется ключ. |
| `vmctl adopt [ИМЯ]` | Перенести фактические параметры одной или всех локальных ВМ в NetBox; требуется ключ. Локальные ВМ и IPAM не меняет. |

`vmctl --dry-run КОМАНДА ...` показывает план без изменений. Дополнительный файл конфигурации задаётся как `vmctl --config /путь/config.toml КОМАНДА ...`. В режиме NetBox команды изменения сначала записывают требуемое состояние в NetBox, затем изменяют локальную ВМ. При локальной ошибке запись NetBox остаётся; проверьте `vmctl audit` и повторите `vmctl sync ИМЯ` после устранения причины.

`vmctl list` обновляет каталог `/opt/vmctl/current-guest`: ссылка с именем каждой ВМ указывает на её постоянный XML libvirt (обычно `/etc/libvirt/qemu/ИМЯ.xml`). Ссылки также обновляются после успешных команд создания, изменения и удаления ВМ. Для просмотра файла используйте, например, `cat /opt/vmctl/current-guest/ИМЯ`; права доступа к XML определяет libvirt. Каталог ссылок не хранится в Git.

Для сверки всего хоста выполните `vmctl --dry-run sync`, затем `vmctl sync`. Команда обрабатывает записи ВМ устройства, указанного в конфигурации хоста, по одной; при ошибке продолжает остальные и в конце показывает число ошибок. Если запись ВМ есть в NetBox, но локальной ВМ нет, она создаётся по записи NetBox. Флаг `--purge` без имени действует на все обрабатываемые ВМ: сначала проверьте план удаления файлов через `vmctl --dry-run sync --purge`.

Если существующая локальная ВМ уже учтена в NetBox, но её `Serial` пуст, выполните `vmctl --dry-run adopt ИМЯ`, затем `vmctl adopt ИМЯ`: команда скопирует UUID и фактическую конфигурацию в NetBox. При расхождении уже заполненного Serial `adopt` и `sync` остановятся. Для новой ВМ `prepare` создаёт UUIDv4 в NetBox до создания локальной ВМ. NetBox не обеспечивает уникальность поля `Serial` самостоятельно.

Параметры графического экрана показывает `vmctl check ИМЯ`: фактические значения берутся из libvirt, требуемые задают в NetBox. Для подключения используйте VNC/SPICE-клиент по указанным адресу и порту.

Для интерфейсов `vmctl` задаёт в libvirt имя TAP-устройства хоста вида `vm-ИМЯ-хеш` (до 15 байт), чтобы его было проще найти через `ip link`. Полное имя ВМ может быть сокращено; хеш различает интерфейсы. `vmctl check ИМЯ` показывает имя хостового интерфейса. Для ранее созданной ВМ с `vnetN` выполните `vmctl --dry-run sync ИМЯ` и `vmctl sync ИМЯ` даже при работающей ВМ; новое имя появится после выключения и запуска.

Команды `disk` и `nic` требуют выключенную ВМ; через NetBox и `sync` изменения можно подготовить заранее, а применить при следующем запуске. При отсутствии ключа новые команды работают только с локальной ВМ. Имя диска и интерфейса состоит из латинских букв, цифр, `.`, `_` и `-`. При ручном добавлении диска в NetBox укажите размер в целых ГиБ; `sync` создаст файл в каталоге хранения. Мост нового интерфейса берётся из `bridge` контекста ВМ, если для него не задан `interface_bridges`. Перед `vmctl sync ИМЯ --purge` проверьте план: этот флаг удалит управляемые файлы дисков, которых уже нет в NetBox, и требует выключенной ВМ. Удалять всю запись ВМ через UI NetBox нельзя: для этого есть `vmctl delete`, сохраняющий возможность повторить операцию после локальной ошибки.

Статусы NetBox используются так: `planned` — запись подготовлена до локального создания; `staged` — ВМ определена, запуск не запрошен; `active` — ВМ должна работать; `offline` — ВМ должна быть выключена. `sync` создаёт отсутствующую локальную ВМ и выполняет переходы питания для `active` и `offline`. Фактическое питание проверяйте командой `vmctl list`.

### Новая ВМ: сначала NetBox, затем хост

Скопируйте подходящий образец в `local/` и укажите имя ВМ и существующие пути к ISO или cloud image на хосте:

```bash
cd /opt/vmctl
mkdir -p local
cp examples/ubuntu-iso.toml local/guest.toml
# Отредактируйте local/guest.toml
vmctl --dry-run prepare local/guest.toml
vmctl prepare local/guest.toml
```

После `prepare` ВМ имеет статус `planned` в NetBox; виртуальный диск, интерфейс и MAC уже созданы, а в libvirt ВМ ещё нет. Откройте запись ВМ в NetBox:

1. Проверьте Description, CPU, память и размер виртуального диска.
2. Назначьте IPv4 и/или IPv6 интерфейсу через IPAM. Если адрес должен быть основным, выберите его как Primary IPv4/IPv6 у ВМ.
3. Задайте тип дисплея, IP хоста, порт и пароль в `local_context_data.vmctl.display`.
4. Проверьте мост и пути в `local_context_data.vmctl`.

Затем примените запись NetBox на хосте:

```bash
vmctl --dry-run sync ИМЯ
vmctl sync ИМЯ
vmctl audit
vmctl start ИМЯ
vmctl list
```

`sync` читает NetBox, создаёт диск и определяет ВМ в libvirt, затем переводит запись из `planned` в `staged`. `start` сначала устанавливает статус `active` в NetBox, затем запускает ВМ. Адреса в NetBox документируют ВМ, но сами по себе не настраивают сеть внутри гостевой ОС: настройте её в установщике или cloud-init.

`source = "iso"` создаёт пустой диск и подключает ISO. `source = "cloud_image"` копирует образ и добавляет cloud-init; для этого используйте `examples/ubuntu-cloud.toml`, замените пример SSH-ключа в `user_data` и установите `xorriso`. Если настройка в NetBox до локального создания не нужна, выполните `vmctl create local/guest.toml`: команда объединяет `prepare` и первый `sync`, сразу создавая локальную ВМ по записи NetBox. Между этапами нельзя вручную назначить IP или изменить дисплей; сделайте это после создания и при необходимости повторите `sync`. Создание определяет ВМ, запуск выполняется отдельно.

### Изменение управляемой ВМ

Для ВМ, созданной текущей версией `vmctl`, меняйте требуемые параметры в NetBox, затем выполняйте `vmctl --dry-run sync ИМЯ` и `vmctl sync ИМЯ`. Работающая ВМ продолжит работать с прежними параметрами; новый постоянный XML применяется при следующем полном выключении и запуске:

```bash
# Измените запись ВМ в NetBox
vmctl --dry-run sync ИМЯ
vmctl sync ИМЯ
# В выбранное время обслуживания:
vmctl shutdown ИМЯ
vmctl start ИМЯ
vmctl audit
```

`shutdown` ждёт фактической остановки ВМ до 60 секунд. Если гостевая ОС или установщик не обрабатывает запрос, команда возвращает ошибку, но NetBox уже хранит требуемый статус `offline`. Проверьте состояние через `vmctl check ИМЯ`; для немедленного выключения используйте `vmctl shutdown ИМЯ --force`. Принудительное выключение не удаляет ВМ или её диски, но может привести к потере незаписанных данных. `vmctl reboot ИМЯ` не применяет ожидающий XML: нужен именно `shutdown`, затем `start`. `sync` записывает постоянный XML в libvirt, сохраняя UUID; `--purge` требует остановленной ВМ. Если нужно изменить только IP-адрес, назначьте его интерфейсу в NetBox и отдельно настройте сеть внутри гостевой ОС; `sync` проверит связь primary IP с интерфейсом.

Размер существующего qcow2 `sync` не меняет. Для переноса файла диска нужна отдельная операция с хранилищем. Дополнительный диск можно добавить в NetBox или командой `vmctl disk add`, затем сверить через `audit`.

Для изменения питания и автозапуска используйте `vmctl start`, `shutdown`, `reboot`, `autostart` и `autostart-off`. При наличии ключа они сначала записывают требуемое состояние в NetBox, затем вызывают libvirt. После ошибки `shutdown` проверьте фактическое состояние через `vmctl list`: NetBox уже хранит запрос `offline`, даже если гостевая ОС ещё работает.

### Учёт существующих ВМ в NetBox

Если виртуализация уже работает, сначала создайте в NetBox кластер и устройство хоста, привяжите устройство к кластеру и настройте ключ в `config.toml`. Затем выполните:

```bash
vmctl check
vmctl audit
vmctl --dry-run adopt
vmctl adopt
vmctl audit
```

`adopt` без имени проходит все локальные ВМ; `adopt ИМЯ` обрабатывает одну. Для отсутствующей записи он создаёт ВМ, Virtual Disks, интерфейсы и MAC. Для существующей записи обновляет CPU, память, Description ВМ, статус, автозапуск и пустой Serial; добавляет, меняет размеры и удаляет Virtual Disks по фактически подключённым дискам и ISO, записывая полный путь каждого в его `Description`; сопоставляет интерфейсы прежде всего по MAC, сохраняя их IP-привязки. Связь Virtual Disk с CD-ROM приводом хранится в `local_context_data.vmctl.mounted_media`. Размер Virtual Disk округляется до целого МиБ вверх. Если лишний интерфейс NetBox имеет IP, операция остановится до записи: сначала разберите его адреса в IPAM вручную. Уже заполненный Serial с другим UUID не перезаписывается. Libvirt и IPAM команда не меняет. Перед применением проверьте вывод `--dry-run`.

У импортированной ВМ источник установки отмечен как `existing`. `sync` может сверить её параметры, записать поддерживаемые изменения в постоянный XML работающей или выключенной ВМ и привести питание к статусу NetBox, но не может воссоздать исчезнувшую локальную ВМ. Подключённые CD-ROM учитываются отдельными Virtual Disks и проверяются `audit`; `sync` их пока не переподключает.

### Проверки и восстановление

`vmctl check` проверяет инструменты, хранилище, мост, libvirt, пулы, сети и доступ к NetBox. `vmctl audit` только читает данные и возвращает код `1` при расхождениях:

| Сообщение `audit` | Действие администратора |
| --- | --- |
| `MISSING NETBOX` | Локальная ВМ отсутствует в NetBox. Если она должна учитываться, проверьте `vmctl --dry-run adopt`, затем выполните `vmctl adopt`. |
| `MISSING LOCAL` | ВМ есть в NetBox, но нет в libvirt. Для созданной через `vmctl` ВМ проверьте `vmctl --dry-run sync ИМЯ`, затем `vmctl sync ИМЯ`. Для импортированной ВМ сначала восстановите её локально. |
| `DIFF` | Сравните требуемые параметры NetBox с фактическими. Поддерживаемые изменения подготовьте через `sync`, затем выключите и запустите ВМ; изменение размера диска и гостевых IP требует отдельных действий. |
| `INVALID` | Проверьте `local_context_data.vmctl`, виртуальный диск, интерфейс, primary MAC и связь primary IP с интерфейсом. Старые записи NetBox могут вообще не иметь контекста `vmctl`. |

При локальной ошибке после записи NetBox автоматического отката нет. Устраните причину, проверьте `vmctl audit` и повторите `vmctl sync ИМЯ`. После частично созданного cloud image может понадобиться ручная проверка файлов диска и cloud-init. Если запись NetBox не удалась, локальное изменение не выполняется.
